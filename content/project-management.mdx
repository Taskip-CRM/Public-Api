# Project Management API

The Project Management API allows you to manage projects, board containers (columns), tasks, labels, assignees, comments, files, discussions and project attributes in your TaskIP workspace.

## Conventions

- **Base path:** all endpoints live under `/api/public-v1`. Send your key in the `X-Secret-Key` header.
- **Project identifier:** `{uuid}` in a path is the project **UUID** (for example `8f6c2d1e-5b7a-4c0e-9a31-2d4b6e8f0a17`). Task `{id}` is the numeric task id.
- **Enums are integers:** project and task `priority` is `0` Low, `1` Medium, `2` High, `3` Urgent. Project `status` is `0` Draft, `1` Pinned, `2` Working, `3` Complete, `4` Archived, `5` Review. Project `privacy` is `0` Private, `1` Public. Project attribute `type` is `0` Priority, `1` Label, `2` Category, `3` Tag, `4` Status.
- **Containers and tasks:** every project has board containers (columns) with a stage category (`backlog`, `todo`, `in_progress`, `review`, `done`). A task's status and completion state follow the container it sits in.
- **Pagination:** list endpoints take `item` (page size, default `10`) and `page`, and return `data`, `links` and `meta`.
- **Errors:** see [Error Responses](#error-responses) for the response shapes.

## Get All Projects

Retrieve a paginated list of the projects the API user can see. Administrators and managers see every project; any other user only sees projects they are a member of. A client user additionally never sees a disabled project.

By default, projects with status `3` (Complete) are left out of the list. Pass `status=3` explicitly to list them.

```http
GET /api/public-v1/project
```

### Request Headers
```http
X-Secret-Key: your-secret-key-here
Content-Type: application/json
```

### Query Parameters
| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `item` | integer | No | Projects per page (default: `10`). `0` returns every project in one response without pagination (`data` only, no `links`/`meta`) |
| `page` | integer | No | Page number |
| `search` | string | No | Matches the project `title` (partial match) |
| `status` | integer | No | Filter by status: `0` Draft, `1` Pinned, `2` Working, `3` Complete, `4` Archived, `5` Review |
| `priority` | integer | No | Filter by priority: `0` Low, `1` Medium, `2` High, `3` Urgent |
| `tag` | integer | No | Only projects carrying this tag attribute id |
| `client_only` | any | No | When present, only projects that have a client are returned |
| `health_band` | string or array | No | Filter by health band (`on_track`, `at_risk`, `off_track`); repeat the parameter (`health_band[]=at_risk`) for several |
| `program_id` | integer or `none` | No | Only projects in this program; `none` returns projects without a program |
| `sort` | string | No | `title`, `due` (end date), `status`, `updated`, or `health`. Without `sort`, newest projects (highest `id`) come first |
| `dir` | string | No | `asc` (default) or `desc`. Applies to `title`, `due`, `status` and `updated` |

### Example Request

```bash
curl -X GET "https://public-api.taskip.net/api/public-v1/project?item=20&status=2&sort=updated&dir=desc" \
  -H "X-Secret-Key: your-secret-key-here" \
  -H "Content-Type: application/json"
```

### Response Notes

- `priority`, `privacy` and `status` are returned as integers (see the enum tables under [Create New Project](#create-new-project)).
- `client`, `project_manager` and `assignees` are deprecated, derived from `members`; prefer `members` and `leads`. `project_manager` is a single user object (the earliest lead), or `[]` when the project has no lead.
- `budget_*` keys are omitted entirely for a client user. `contract_value` is omitted unless the API user has permission to view project rates.
- `health` is `{ "score", "band", "computed_at" }` when a health band has been computed, otherwise `null`. `program` is `{ "id", "uuid", "name", "color" }` or `null`.
- `tags` and `categories` items come from project attributes: `type` is `3` for tags and `2` for categories.

## Create New Project

Create a new project. The API user becomes the creator (`created_by`); a `created_by` value in the body is ignored. Five default board containers are created for every project (`Backlog`, `To Do`, `In Progress`, `Review`, `Done`).

```http
POST /api/public-v1/project
```

### Request Body

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `title` | string | Yes | Project title (max 191 characters) |
| `priority` | integer | Yes | `0` Low, `1` Medium, `2` High, `3` Urgent |
| `privacy` | integer | Yes | `0` Private, `1` Public |
| `status` | integer | Yes | `0` Draft, `1` Pinned, `2` Working, `3` Complete, `4` Archived, `5` Review |
| `description` | string | No | Project description |
| `started_at` | string | No | Start date, e.g. `2024-03-01` |
| `ended_at` | string | No | End date, e.g. `2024-09-01` |
| `key` | string | No | Short project key (2-10 uppercase letters or digits, starting with a letter). Must be unique; derived from the title when omitted |
| `tags` | array | No | Tag attribute ids (type `3`) |
| `category` | array | No | Category attribute ids (type `2`) |
| `members` | array | No | Project members: `[{ "user_id": 8, "role": "member" }]`. `role` is one of `lead`, `member`, `viewer`, `client`. When sent, it takes precedence over the legacy `client`, `assignee` and `project_manager` fields |
| `client` | array | No | Legacy: client user ids (become `client` members) |
| `assignee` | array | No | Legacy: team member user ids (become `member` members) |
| `project_manager` | integer | No | Legacy: a single user id (becomes `lead`) |
| `notify_client` | boolean | No | Send a notification email to the client (default `false`) |
| `allow_manual_time_tracking` | boolean | No | Default `true` |
| `show_time_details_to_client` | boolean | No | Default `true` |
| `allow_team_member_task_create` | boolean | No | Default `true` |
| `allow_client_task_create` | boolean | No | Defaults to the value of `client_intake_enabled` (`true` when that is omitted) |
| `task_move_access` | string | No | `managers`, `own` or `all` |
| `task_status_access` | string | No | `managers`, `own` or `all` |
| `task_priority_access` | string | No | `managers`, `own` or `all` |
| `billing_type` | string | No | `hourly`, `fixed_price`, `retainer`, `non_billable` or `internal` |
| `default_billable` | boolean | No | Whether new time entries are billable by default |
| `billable_rate` | number | No | Min `0` |
| `cost_rate` | number | No | Min `0` |
| `currency` | string | No | 3-letter currency code, e.g. `USD` |
| `billing_profile_id` | integer | No | Must exist in billing profiles |
| `budget_hours` | number | No | Hours cap, `0.01` to `99999999.99`. `null` means no cap |
| `budget_amount` | number | No | Amount cap, `0.01` to `999999999999.99`. `null` means no cap |
| `budget_cap_mode` | string | No | `hard`, `overrun_limited` or `warn_only`. Must be a mode the workspace policy allows |
| `budget_overrun_percent` | number | No | Greater than `0`, max `100`. Required when the mode is `overrun_limited` and no default is configured |
| `budget_alert_thresholds` | array | No | Up to 10 integers between `1` and `100` |
| `contract_value` | number | No | Planned revenue (`0.01` to `999999999999.99`). Refused with a validation error unless the API user may view project rates |
| `show_financials_to_client` | boolean | No | Same permission rule as `contract_value` |
| `default_client_visible` | boolean | No | Default `true` |
| `client_intake_enabled` | boolean | No | Default `true` |
| `client_intake_types` | array | No | One or more of `feedback`, `bug`, `change_request` |
| `auto_shift_dependents` | boolean | No | Default `false` |
| `methodology` | string | No | `kanban` or `scrum` |
| `estimate_unit` | string | No | `hours` or `points` |
| `client_voting_enabled` | boolean | No | Default `false` |
| `show_health_to_client` | boolean | No | Default `false` |

### Enum Reference

| Field | Values |
|-------|--------|
| `priority` | `0` Low, `1` Medium, `2` High, `3` Urgent |
| `privacy` | `0` Private, `1` Public |
| `status` | `0` Draft, `1` Pinned, `2` Working, `3` Complete, `4` Archived, `5` Review |

### Error Responses

Validation failure (HTTP `422`):

```json
{
  "error": {
    "title": ["The title field is required."],
    "priority": ["The selected priority is invalid."]
  }
}
```

Permission refusal (HTTP `422`), when the API user is not allowed to create projects:

```json
{
  "error": {
    "msg": ["You don't have permission to create project"]
  }
}
```

Business-rule failure (HTTP `422`), for example a member role that is not valid for that user:

```json
{ "msg": "<reason>" }
```

## Get Specific Project

Retrieve a single project by its UUID. Returns `404` when the project does not exist or the API user is not allowed to see it (non-admin users must be a member of the project).

```http
GET /api/public-v1/project/{uuid}
```

### Path Parameters
| Parameter | Type | Description |
|-----------|------|-------------|
| `uuid` | string | Project UUID |

### Example Request

```bash
curl -X GET "https://public-api.taskip.net/api/public-v1/project/8f6c2d1e-5b7a-4c0e-9a31-2d4b6e8f0a17" \
  -H "X-Secret-Key: your-secret-key-here"
```

## Update Project

Update a project. The body is **partial**: only the keys you send are written; anything you omit is left untouched.

- `tags`, `category` and `members` (or the legacy `client`, `assignee`, `project_manager`) **replace** the existing relation when sent. Sending `"tags": []` clears all tags.
- Sending `null` for `budget_hours`, `budget_amount` or `contract_value` removes that cap/value.
- `task_move_access`, `task_status_access` and `task_priority_access` fall back to their defaults (`own`, `own`, `managers`) if sent as `null`.

```http
PUT /api/public-v1/project/{uuid}
PATCH /api/public-v1/project/{uuid}
```

### Path Parameters
| Parameter | Type | Description |
|-----------|------|-------------|
| `uuid` | string | Project UUID (a numeric project id is also accepted) |

### Request Body

Any of the fields from [Create New Project](#create-new-project), all optional on update. If a field is sent, the create-time validation rules still apply to it (for example `title` cannot be empty and `priority` must be `0`-`3`). `key` cannot be changed through this endpoint.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `title` | string | No | Max 191 characters; cannot be null when sent |
| `description` | string | No | May be `null` |
| `priority` | integer | No | `0`-`3` |
| `privacy` | integer | No | `0` or `1` |
| `status` | integer | No | `0`-`5` |
| `started_at` / `ended_at` | string | No | May be `null` |
| `tags` | array | No | Replaces the project's tags |
| `category` | array | No | Replaces the project's categories |
| `members` | array | No | Replaces the project's members (`[{ "user_id", "role" }]`) |
| `budget_hours` / `budget_amount` | number | No | `null` removes the cap |
| `methodology` | string | No | `kanban` or `scrum`. Switching a scrum project with an active sprint to `kanban` is refused |

### Example Request

```bash
curl -X PUT "https://public-api.taskip.net/api/public-v1/project/8f6c2d1e-5b7a-4c0e-9a31-2d4b6e8f0a17" \
  -H "X-Secret-Key: your-secret-key-here" \
  -H "Content-Type: application/json" \
  -d '{
    "status": 5,
    "ended_at": "2024-05-01",
    "tags": [4, 7],
    "budget_amount": null
  }'
```

### Example Response

```json
{
  "msg": "Project Updated",
  "status": 200,
  "data": {
    "id": 12,
    "title": "Website Redesign - Acme Corp",

```

The `data` object is the full single-project resource described in [Get Specific Project](#get-specific-project); it is abbreviated here.

### Error Responses

Project not found (HTTP `404`):

```json

```

## Get All Tasks List

## Update Task

Update a task. `title` and `container_id` are always required (the container must belong to this project). Every other column is **partial**: only the keys present in the request are written, so omitting `description`, `due_date`, `started_at`, `order`, `story_points`, `sprint_id` or `custom_fields` leaves the stored value untouched. Send `null` to clear a nullable value.

Fields that are only written when sent: `priority`, `status`, `type`, `client_visible`, `milestone_id`.

```http
PUT /api/public-v1/project/{uuid}/task/{id}
```

### Path Parameters
| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `uuid` | string | Yes | Project UUID |
| `id` | integer | Yes | Task id |

### Request Body

Same fields and rules as [Create Task](#create-task). Differences on update:

| Field | Behavior on update |
|-------|--------------------|
| `assignees` | When non-empty, the task's assignees are synced to exactly this list (missing members are removed). An empty or omitted list leaves assignees unchanged |
| `labels` | When non-empty, the task's labels are synced to exactly this list of label attribute ids. An empty or omitted list leaves labels unchanged |
| `documents` | When non-empty, the task's documents are synced to exactly this list of document ids. An empty or omitted list leaves documents unchanged |
| `status` | Written as sent |
| `type`, `priority`, `client_visible`, `milestone_id` | Written only when sent. `origin` is never changed |
| `milestone_id` | Must belong to this project, otherwise `422`. It cannot be cleared through this endpoint |
| `sprint_id` | Must belong to this project, otherwise `422`. Only applied when the project is a scrum project (a kanban project ignores it) and only when sent; leaving it out keeps the task's current sprint |

### Example Response

```json
{
  "msg": "Project Category Updated"
}
```

## Error Responses

Errors in this API come in a few shapes. Check the HTTP status first, then the body.

### Common Status Codes

| Status Code | Meaning | Typical cause |
|-------------|---------|---------------|
| `401` | Unauthorized | `X-Secret-Key` header missing: `{ "message": "Secret keys are missing." }` |
| `404` | Not Found | Unknown secret key (`{ "status": 404, "msg": "Workspace not found" }`), or a project, task, comment, member or attribute that does not exist or is not visible to the API user |
| `409` | Conflict | Task cannot be deleted because it has tracked time |
| `422` | Unprocessable | Validation failed, a business rule refused the request, or the API user lacks permission |
| `429` | Too Many Requests | Rate limit exceeded |
| `500` | Server Error | Unexpected failure |

### Validation Errors: `error` keyed by field

Request validation for project create/update, task create/update, labels, comments, task files, discussion, containers and attributes returns HTTP `422`:

```json
{
  "error": {
    "title": ["The title field is required."],
    "priority": ["The selected priority is invalid."]
  }
}
```

### Validation Errors: `errors` keyed by field

Endpoints that validate inline (All Tasks List, Change Project Priority/Status/Category, Bulk Update Tags/Categories) and Change Task Order return HTTP `422`:

```json
{
  "success": false,
  "message": "Validation failed",
  "errors": {
    "category": ["The category field is required."]
  }
}
```

### Permission Refusals and Container Lookups: `error.msg`

Permission refusals (Create Project, Update Project, Delete Project, Change Project Priority/Status/Category, Delete Attribute) and container lookups that fail return HTTP `422` with a list of messages under `error.msg`. Create Project and Delete Project check the permissions of the API key's user; some project-level role and scope checks (for example on Update Project) are bypassed for API-key requests, so those variants are not expected in practice. The container lookups (`Container not found`, `title field is required`) are:

```json
{
  "error": {
    "msg": ["You don't have permission to update project"]
  }
}
```

### Plain `msg` Errors

Lookups and business-rule failures return a single `msg`:

```json
{ "msg": "We couldn't find this task." }
```

The status code tells them apart: `404` for a missing resource, `422` for a rule such as `Target container not found`, `Please select a member to assign.`, `The milestone belongs to another project.`, `The container belongs to another project.` or `Invalid priority value`, and `409` for a task that has tracked time. A few endpoints return additional keys, for example `entry_count` on the `409` and `data.open_items` when [Change Project Status](#change-project-status) is blocked by the close-out checklist.
