# Inbox Management API

The Inbox Management API provides comprehensive email conversation handling and communication management capabilities. This powerful API allows you to manage email threads, assign tags, reply to conversations, and organize your communication workflow efficiently.

## Overview

Inbox Management consists of:
- **Conversations**: List inbox conversations (threads) by folder
- **Messaging**: Send a new email and reply to an existing conversation (queued for delivery)
- **Tags**: Create, list, update and delete inbox tags, and assign tags to conversations
- **Inbox Address**: Get the workspace inbox (forwarding / connected) email address

## Authentication, Limits and Common Behavior

Every request must send the secret key header:

```http
X-Secret-Key: your-secret-key-here
Content-Type: application/json
```

The two sending endpoints (`new-message` and `{uuid}/reply`) are protected by extra middleware:

| Rule | Behavior |
|------|----------|
| Paid workspace only | On a non-paid workspace the request is not processed and the API responds `403` with `{"success": false, "message": "Only paid users are allowed"}` |
| Inbox email send limit | **10 requests per day and 100 per month per workspace** (counted for the `inbox` type). Over the limit: `429` with `{"success": false, "message": "Your workspace has exceeded the inbox email sending limit"}` |
| Request throttle | 10 requests per minute (`429` when exceeded) |
| Plan inbox email limit | If the plan's inbox email limit is reached: `422` with `{"status": 422, "msg": "...", "limit_info": {...}, "upgrade_required": true}` |

Validation failures return `422` with `{"error": {"field": ["message"]}}`. Business-rule errors return `422` with `{"error": {"msg": ["message"]}}`, unless a section below shows a different shape.

## Get All Conversations

Retrieve conversations (root messages of each thread) for a folder, ordered by latest activity (newest first).

```http
GET /api/public-v1/inbox/conversation/all
```

### Query Parameters
| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `folder` | string | No | `inbox` (default), `sent`, `drafts`, `outbox`, `archive`, `trash`, `spam` |
| `item` | integer | No | Items per page (default: `10`). Use `0` to return all |
| `page` | integer | No | Page number |
| `search` | string | No | Search term for conversations |

Results are limited to the mailboxes the secret key's user is allowed to access.

## Create New Message/Conversation

Send a new email. The message is queued for delivery. One conversation is created for each address in `to_emails`.

```http
POST /api/public-v1/inbox/conversation/new-message
```

See [Authentication, Limits and Common Behavior](#authentication-limits-and-common-behavior) for the paid-plan check, 10/day and 100/month limits, and throttling.

### Request Body

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `subject` | string | Yes | Email subject |
| `to_emails` | array | Yes (in practice) | Recipient email addresses. Also accepts a comma-separated string or a JSON array string. It is not validated by the request class; if no valid recipient results, the API returns `422` `{"msg": "No valid recipient addresses were provided."}` |
| `message` | string | No | Message body (HTML supported) |
| `cc` | string | No | Comma-separated CC addresses |
| `bcc` | string | No | Comma-separated BCC addresses |
| `cc_emails` | array | No | CC addresses as an array (takes precedence over `cc`) |
| `bcc_emails` | array | No | BCC addresses as an array (takes precedence over `bcc`) |
| `from_email` | string | No | Sending address. Defaults to the workspace connected email |
| `attachments` | array | No | Array of objects with a media ID: `[{"id": 12}]` |
| `draft_uuid` | string | No | UUID of a draft (or failed outbox item) to send instead of creating a new conversation |

The sending address must have verified DNS and cannot be a platform default `*.taskip.email` address.

<ApiTester
  endpoint="/api/public-v1/inbox/conversation/new-message"
  method="POST"
  defaultBody={{
    to_emails: ["client@example.com"],
    subject: "Project Update - Website Development",
    message: "<p>Hi there,</p><p>I wanted to provide you with an update...</p>",
    cc: "manager@taskip.com"
  }}
  description="Test sending a new message"
/>

### Example Request

```bash
curl -X POST "https://public-api.taskip.net/api/public-v1/inbox/conversation/new-message" \
  -H "X-Secret-Key: your-secret-key-here" \
  -H "Content-Type: application/json" \
  -d '{
    "to_emails": ["client@example.com"],
    "subject": "Project Update - Website Development",
    "message": "<p>Hi there,</p><p>I wanted to provide you with an update...</p>",
    "cc": "manager@taskip.com",
    "bcc": "archive@taskip.com"
  }'
```

### Example Response

Status `202 Accepted`:

```json
{
  "data": {
    "message_id": "0b2f8c9e-3a7d-4f5e-8b1c-6d4e2a9f7c10",
    "in_reply_to": null,
    "reply_to": "client@example.com",
    "from_email": "support@yourcompany.com",
    "from_name": "Your Company",
    "to_email": "client@example.com",
    "cc_emails": "manager@taskip.com",
    "bcc_emails": "archive@taskip.com",
    "subject": "Project Update - Website Development",
    "is_read": true,
    "created_at": "2024-01-15T10:30:00+00:00",
    "uuid": "7e1d5a3c-2b4f-4c8a-9d6e-1f0a3b5c7d92",
    "body_plain": "Hi there, I wanted to provide you with an update...",
    "tags": [],
    "replied_by": null,
    "send_type": true,
    "send_emails": null
  },
  "send_emails": ["client@example.com"],
  "msg": "Email queued — you will be notified when it is sent"
}
```

When several recipients are given, `data` is the last conversation created and `send_emails` lists every recipient.

### Errors

| Status | Response |
|--------|----------|
| `422` | Missing `subject`: `{"error": {"subject": ["The subject field is required."]}}` |
| `422` | `{"msg": "Workspace connected mail not found"}` |
| `422` | `{"msg": "...", "error_type": "dns_not_verified", "email": "...", "domain": "...", "action_required": "...", "help_url": "..."}` |
| `422` | `{"msg": "...", "error_type": "taskip_email_not_allowed", "email": "..."}` |
| `422` | Plan inbox email limit reached (`upgrade_required: true`) |
| `429` | Daily/monthly send limit or per-minute throttle exceeded |

## Reply to Conversation

Reply to an existing conversation. The reply is queued for delivery.

```http
POST /api/public-v1/inbox/conversation/{uuid}/reply
```

See [Authentication, Limits and Common Behavior](#authentication-limits-and-common-behavior) for the paid-plan check, 10/day and 100/month limits, and throttling.

### Path Parameters
| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `uuid` | string | Yes | Conversation UUID |

### Request Body

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `msg` | string | Yes | Reply body (HTML supported) |
| `type` | integer | Yes | `0` or `1`. Required by validation; the reply logic does not use it |
| `replyFrom` | string | No | Sending address. Defaults to the address the conversation was received on |
| `to_emails` | array | No | Replaces the default recipient (the original `Reply-To`, or the sender) |
| `cc` / `bcc` | string | No | Comma-separated addresses |
| `cc_emails` / `bcc_emails` | array | No | Addresses as an array (take precedence over `cc` / `bcc`) |
| `attachments` | array | No | Array of objects with a media ID: `[{"id": 12}]` |
| `schedule_time` | string | No | Accepted by validation but not used by the reply logic |

<ApiTester
  endpoint="/api/public-v1/inbox/conversation/9c4a1f4e-6c1b-4b6e-9a55-0d6a1c7f2e11/reply"
  method="POST"
  defaultBody={{
    msg: "<p>Thank you for your message. I will review and respond soon.</p>",
    type: 0
  }}

```bash

  -H "Content-Type: application/json" \
```

```json
    "cc_emails": null,
    "bcc_emails": null,
    "subject": "Re: Project Discussion - Website Redesign",
    "is_read": true,
    "delivered": false,
```

### Errors

| Status | Response |
|--------|----------|
| `422` | Missing `msg` or `type`: `{"error": {"msg": ["The msg field is required."]}}` |
| `422` | `{"error": {"msg": ["Conversation not found"]}}` |
| `422` | `{"error": {"msg": ["You do not have permission to access this conversation"]}}` |
| `422` | `{"msg": "...", "error_type": "no_reply_address"}`, `dns_not_verified`, or `taskip_email_not_allowed` |
| `422` | Plan inbox email limit reached (`upgrade_required: true`) |
| `429` | Daily/monthly send limit or per-minute throttle exceeded |

## Assign Tags to Conversation

Set the tags of a conversation. The submitted list **replaces** the conversation's current tags. Send an empty list (or omit `tags`) to remove all tags.

```http
POST /api/public-v1/inbox/conversation/{uuid}/assign-tags
```

### Path Parameters
| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `uuid` | string | Yes | Conversation UUID |

### Request Body

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `tags` | array of integers | No | IDs of existing tags (see [List Tags](#list-tags)). An empty array or omitted field detaches all tags |

<ApiTester
  endpoint="/api/public-v1/inbox/conversation/9c4a1f4e-6c1b-4b6e-9a55-0d6a1c7f2e11/assign-tags"
  method="POST"
  defaultBody={{
    tags: [1, 2]
  }}
  description="Test assigning tags to a conversation"
/>

### Example Request

```bash
curl -X POST "https://public-api.taskip.net/api/public-v1/inbox/conversation/9c4a1f4e-6c1b-4b6e-9a55-0d6a1c7f2e11/assign-tags" \
  -H "X-Secret-Key: your-secret-key-here" \
  -H "Content-Type: application/json" \
  -d '{ "tags": [1, 2] }'
```

### Example Response

```json
{ "msg": "Tag assigned" }
```

When all tags are removed: `{"msg": "Tag detached"}`.

### Errors

- `404` `{"msg": "Conversation not found"}`
- `403` `{"msg": "You do not have permission to access this conversation"}`

## Create a Tag

```http
POST /api/public-v1/inbox/assign-tags
```

### Request Body

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `name` | string | Yes | Tag name (max 191 characters) |
| `color` | string | No | Tag color (max 98 characters) |

### Example Request

```bash
curl -X POST "https://public-api.taskip.net/api/public-v1/inbox/assign-tags" \
  -H "X-Secret-Key: your-secret-key-here" \
  -H "Content-Type: application/json" \
  -d '{ "name": "Client Communication", "color": "blue" }'
```

### Example Response

```json
{
  "msg": "Tag added successfully",
  "tag": { "id": 3, "name": "Client Communication", "color": "blue" }
}
```

### Errors

- `422` `{"error": {"name": ["The name field is required."]}}`
