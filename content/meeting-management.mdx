# Meeting Management API

The Meeting Management API lets you read the meetings (booking pages) configured in your TaskIP workspace and work with their bookings: list meetings, inspect a meeting and its booking form, list and inspect bookings, and create a booking for an available time slot.

## Overview

The public API exposes:
- **Meetings**: list meetings and fetch the full configuration of one meeting (host, availability, booking form, customisation)
- **Bookings**: list the bookings of a meeting and fetch a single booking
- **Booking creation**: book a time slot on a meeting

Meetings themselves are created and edited in the TaskIP application; this API does not create, update, or delete meetings or bookings other than creating a booking.

## Main Endpoints Overview

| Method | Endpoint | Description |
|--------|----------|-------------|
| `GET` | [`/api/public-v1/meeting-list`](#get-all-meetings) | Get all meetings |
| `GET` | [`/api/public-v1/meeting/details/{uuid}`](#get-meeting-details) | Get meeting details |
| `GET` | [`/api/public-v1/meeting/{uuid}/booking-list`](#get-meeting-booking-list) | Get booking list for a meeting |
| `GET` | [`/api/public-v1/meeting/{uuid}/booking/details/{id}`](#get-booking-details) | Get specific booking details |
| `POST` | [`/api/public-v1/meeting/{uuid}/booking`](#book-a-meeting) | Book a meeting slot |

## Get All Meetings

Retrieve a list of all meetings in your system.

```http
GET /api/public-v1/meeting-list
```

### Request Headers
```http
X-Secret-Key: your-secret-key-here
Content-Type: application/json
```

### Query Parameters
| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `page` | integer | No | Page number for pagination (default: 1) |
| `item` | integer | No | Meetings per page (default: 10). Use `0` to return all meetings without pagination |
| `search` | string | No | Search by meeting title |

Results are ordered by `id` descending.

## Book a Meeting

Create a new booking for an available meeting slot. The booking form fields are validated against the meeting's booking form (see `form.fields` in [Get Meeting Details](#get-meeting-details)).

```http
POST /api/public-v1/meeting/{uuid}/booking
```

### Path Parameters
| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `uuid` | string | Yes | Meeting UUID |

### Request Body

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `date` | string | Yes | Booking date (`YYYY-MM-DD`), in the `timezone` given below |
| `time_slot_start` | string | Yes | Start time (`HH:MM`) |
| `time_slot_end` | string | Yes | End time (`HH:MM`) |
| `booking_data` | object | Yes | Booking form answers, keyed by `<field_id>____<field_name>` for each field of the meeting's booking form (for example `f_8a1b2c____email`). Field validation (required, email, number, ...) follows the form configuration |
| `guest_email` | array | No | Array of guest email addresses. May be omitted (treated as no guests) or sent as `[]` |
| `timezone` | string | No | Timezone of `date` / `time_slot_*` (defaults to the workspace timezone). Times are converted to the workspace timezone for storage |

The first name, last name and email of the booker are read from the form's `name` (`..____first_name`, `..____last_name`) and `email` (`..____email`) fields.

### Error Responses

| Status | When | Body |
|--------|------|------|
| `422` | `date`, `time_slot_start`, `time_slot_end`, or `booking_data` is missing | `{"error": {"date": ["The date field is required."]}}` |
| `422` | The meeting UUID does not exist | `{"error": {"msg": ["meeting not found"]}}` |
| `422` | The slot overlaps an existing booking | `{"error": {"msg": ["This time slot is already booked. Please select a different time."]}}` |
| `422` | `booking_data` fails the booking form's validation | `{"error": {"<field_id>____<field_name>": ["..."]}, "status": 422}` |
| `403` | No price plan found for the workspace | `{"msg": "Price plan not found"}` |

---

<Callout type="info" emoji="📅">
  **Meeting Integration**: Meetings can use Google Meet or Zoom (`method` `2` and `3`) for video conferencing and automatic meeting link generation.
</Callout>


<Callout type="warning" emoji="⏰">
  **Time Zones**: Always send the `timezone` that `date` and `time_slot_start` / `time_slot_end` are expressed in. Times are converted to the workspace timezone before the booking is stored.
</Callout>
