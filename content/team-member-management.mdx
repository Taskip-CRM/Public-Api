# Team Member Management API

The Team Member Management API allows you to manage team members and users in your TaskIP system. You can invite, read, update, and delete team members, as well as perform bulk deletes.

<Callout type="info" emoji="💡">
  **Resource IDs**: The `{id}` segment of the team member routes only accepts digits. A non-numeric segment is a `404`.
</Callout>

## Endpoints Overview

| Method | Endpoint | Description |
|--------|----------|-------------|
| `GET` | [`/api/public-v1/team-member`](#get-all-team-members) | Get all team members |
| `POST` | [`/api/public-v1/team-member`](#create-a-team-member) | Invite a new team member |
| `GET` | [`/api/public-v1/team-member/{id}`](#get-a-specific-team-member) | Get a specific team member |
| `PUT` / `PATCH` | [`/api/public-v1/team-member/{id}`](#update-a-team-member) | Update a team member |
| `DELETE` | [`/api/public-v1/team-member/{id}`](#delete-a-team-member) | Delete a team member |
| `POST` | [`/api/public-v1/team-member/bulk-delete`](#bulk-delete-team-members) | Delete multiple team members |

## Get All Team Members

Retrieve a list of all team members in your system.

```http
GET /api/public-v1/team-member
```

<ApiTester
  endpoint="/api/public-v1/team-member"
  method="GET"
  description="Retrieve all team members from your TaskIP system with filtering options"
/>

### Request Headers
```http
X-Secret-Key: your-secret-key-here
Content-Type: application/json
```

### Query Parameters
| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `page` | integer | No | Page number for pagination (default: 1) |
| `item` | integer | No | Team members per page (default: 10). Use `0` to return all team members without pagination |
| `search` | string | No | Search by name or email |
| `active_only` | boolean | No | When true, only active members are returned |

Users of type contact (clients) are never included. Results are ordered by `id` descending.

### Example Request

```bash
curl -X GET "https://public-api.taskip.net/api/public-v1/team-member?page=1&item=20&search=john" \
  -H "X-Secret-Key: your-secret-key-here" \
  -H "Content-Type: application/json"
```

### JavaScript Example
```javascript
const response = await fetch('https://public-api.taskip.net/api/public-v1/team-member?active_only=1', {
  method: 'GET',
  headers: {
    'X-Secret-Key': 'your-secret-key-here',
    'Content-Type': 'application/json'
  }
});

const teamMembers = await response.json();
```

## Create a Team Member

Invite a new team member to your workspace. The member is created with a pending invitation and, unless `send_invite` is `false`, an invitation email is sent immediately.

```http
POST /api/public-v1/team-member
```

<ApiTester
  endpoint="/api/public-v1/team-member"
  method="POST"
  defaultBody={{
    "email": "john.smith@taskip.com",
    "first_name": "John",
    "last_name": "Smith",
    "position": "Senior Developer",
    "role_id": 3,
    "team_ids": [1],
    "send_invite": true
  }}
  description="Test inviting a new team member to your TaskIP workspace"
/>

### Request Headers
```http
X-Secret-Key: your-secret-key-here
Content-Type: application/json
```

### Request Body

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `email` | string | Yes | Team member's email address (must pass DNS validation). Must not already belong to a client, lead, or another account in this workspace |
| `first_name` | string | Yes | First name (max 191 characters). Markup and characters other than letters, spaces, apostrophes, hyphens and dots are stripped |
| `last_name` | string | Yes | Last name (max 191 characters). Sanitized the same way as `first_name` |
| `position` | string | No | Job position/title (max 191 characters) |
| `role_id` | integer | Yes | Role ID, see [Roles](#roles) |
| `team_ids` | array | No | Array of team IDs to add the member to |
| `image` | integer | No | Image/avatar media upload ID |
| `send_invite` | boolean | No | Send the invitation email now (default: `true`). When `false` the member is created without an email being sent |

### Example Request

```bash
curl -X POST "https://public-api.taskip.net/api/public-v1/team-member" \
  -H "X-Secret-Key: your-secret-key-here" \
  -H "Content-Type: application/json" \
  -d '{
    "email": "alice.johnson@taskip.com",
    "first_name": "Alice",
    "last_name": "Johnson",
    "position": "Frontend Developer",
    "role_id": 3,
    "team_ids": [1]
  }'
```

### Python Example
```python
import requests

headers = {
    'X-Secret-Key': 'your-secret-key-here',

}

team_member_data = {

response = requests.post(
    'https://public-api.taskip.net/api/public-v1/team-member',

    json=team_member_data
)

result = response.json()
```

## Update a Team Member

Update an existing team member's information.

```http
PUT /api/public-v1/team-member/{id}
PATCH /api/public-v1/team-member/{id}
```

`PUT` and `PATCH` are handled identically. The `{id}` is the numeric team member (user) ID. The caller needs the `teams` **edit** permission, and the permission rules in [Permissions and Role Rules](#permissions-and-role-rules) apply.

<ApiTester
  endpoint="/api/public-v1/team-member/1"
  method="PUT"
  defaultBody={{
    "email": "alice.johnson@company.com",
    "first_name": "Alice",
    "last_name": "Johnson",
    "position": "Lead Frontend Developer",
    "role_id": 3,
    "team_ids": [1],
    "image": 150
  }}
  description="Test updating a team member's information"
/>

### Path Parameters
| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `id` | integer | Yes | Team member ID to update (digits only) |

### Request Body

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `first_name` | string | Yes | Max 191 characters. HTML and characters other than letters, spaces, apostrophes, hyphens and periods are stripped |
| `last_name` | string | Yes | Max 191 characters, sanitized the same way |
| `role_id` | integer | Yes | See [Roles](#roles). You cannot assign a role above your own |
| `email` | string | No | Valid email. Must not belong to another user, lead or contact; the member being edited is excluded from that check, so re-sending their current email is fine. When omitted or `null`, the stored email is kept |
| `position` | string | No | Max 191 characters. Partial: when omitted, the stored position is kept; send `null` or an empty value to clear it |
| `team_ids` | array | No | When non-empty, replaces the member's current team memberships |
| `image` | integer | No | ID of an existing media upload. When it matches, replaces the member's current image |

`send_invite` has no effect on update.

### Example Request

```bash
curl -X PUT "https://public-api.taskip.net/api/public-v1/team-member/26" \
  -H "X-Secret-Key: your-secret-key-here" \
  -H "Content-Type: application/json" \
  -d '{
    "email": "alice.johnson@company.com",
    "first_name": "Alice",
    "last_name": "Johnson",
    "position": "Lead Frontend Developer",
    "role_id": 3,
    "team_ids": [1],
    "image": 150
  }'
```

### Example Response

```json
{
  "msg": "Team Member updated successfully"
}
```

A rejected update (permission rules, validation) returns `422` with `{"error": {"msg": ["..."]}}` or field errors. An unknown ID returns `404`.

## Delete a Team Member

Delete a specific team member from your system.

```http
DELETE /api/public-v1/team-member/{id}
```

<ApiTester
  endpoint="/api/public-v1/team-member/1"
  method="DELETE"
  description="Test deleting a team member (use with caution)"
/>

### Path Parameters
| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `id` | integer | Yes | Team member ID to delete (digits only) |

<Callout type="warning" emoji="⚠️">
  **Warning**: Deleting a team member revokes their workspace access and removes their image and team memberships. This action cannot be undone. The caller needs the `teams` **delete** permission, and the [permission rules](#permissions-and-role-rules) apply.
</Callout>

### Example Request

```bash
curl -X DELETE "https://public-api.taskip.net/api/public-v1/team-member/26" \
  -H "X-Secret-Key: your-secret-key-here"
```

### Example Response

```json
{
  "msg": "Team member access revoked successfully"
}
```

If no user has that ID, the API returns `404` with `{"msg": "Team Member not found"}`. The workspace owner cannot be removed (`422`).

## Bulk Delete Team Members

Delete multiple team members at once. The caller needs the `teams` **delete** permission. The whole batch is checked first: if any member is one the caller may not act on, or is the workspace owner, nothing is deleted and `422` is returned.

```http
POST /api/public-v1/team-member/bulk-delete
```

<ApiTester
  endpoint="/api/public-v1/team-member/bulk-delete"
  method="POST"
  defaultBody={{
    "ids": [1, 2, 3, 4]
  }}
  description="Test bulk deleting multiple team members (use with caution)"
/>

### Request Body

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `ids` | array | Yes | Array of team member IDs to delete (max 1000 items) |
| `ids.*` | integer | Yes | Each ID must be an integer that exists in the users table |

### Example Request

```bash
curl -X POST "https://public-api.taskip.net/api/public-v1/team-member/bulk-delete" \
  -H "X-Secret-Key: your-secret-key-here" \
  -H "Content-Type: application/json" \
  -d '{
    "ids": [24, 25, 27, 28]
  }'
```

### JavaScript Example
```javascript
const bulkDeleteData = {
  ids: [24, 25, 27, 28]
};

const response = await fetch('https://public-api.taskip.net/api/public-v1/team-member/bulk-delete', {
  method: 'POST',
  headers: {
    'X-Secret-Key': 'your-secret-key-here',
    'Content-Type': 'application/json'
  },
  body: JSON.stringify(bulkDeleteData)
});

const result = await response.json();
```

### Example Response

```json
{
  "msg": "Team members access revoked successfully"
}
```

If none of the IDs match a team member, the API returns `404` with `{"msg": "Team Member not found"}`.

## Permissions and Role Rules

Update, delete and bulk delete share these rules:

- The caller needs the `teams` edit (update) or delete (delete, bulk delete) permission.
- Administrators can only be modified or removed by an Administrator; Managers only by an Administrator or Manager.
- The workspace owner can only be modified by themselves, cannot be removed, and cannot be demoted from Administrator.
- A role cannot assign a role above its own (see [Roles](#roles)).

---

## Roles

`role_id` must be an integer. The built-in role IDs are listed below.

| `role_id` | Role | Notes |
|-----------|------|-------|
| `1` | Administrator | Can only be assigned by the workspace owner |
| `2` | Manager | Can only be assigned by an Administrator or Manager |
| `3` | Member | |
| `4` | Client | |

## Error Responses

### Common Error Codes

| Status Code | Error Type | Description |
|-------------|------------|-------------|
| `401` | Unauthorized | Invalid or missing X-Secret-Key |
| `404` | Not Found | A non-numeric ID in the path, or an unknown team member ID (show, delete, bulk delete) |
| `422` | Validation Error | Request data failed validation, or the operation was rejected (plan limit, insufficient permission or role, workspace owner protection) |
| `429` | Too Many Requests | Rate limit exceeded |

### Example Error Response

Validation failures return `422` with the failing fields under `error`:

```json
{
  "error": {
    "email": ["The email field is required."],
    "role_id": ["You are not allowed to assign the Administrator role."]
  }
}
```

## Best Practices

### Team Management
1. **Role Assignment**: Assign appropriate roles based on job functions
2. **Regular Reviews**: Periodically review team member access
3. **Deferred invites**: Use `send_invite: false` to create members now and send the invitation later

### User Onboarding
1. **Welcome Emails**: Use invitation emails for new team members
2. **Profile Completion**: Encourage complete profile setup
3. **Access Reviews**: Regular access reviews and updates

<Callout type="info" emoji="💡">
  **Tip**: Use `active_only=1` on the GET /team-member endpoint to build member pickers that exclude people who have not yet accepted their invitation.
</Callout>
