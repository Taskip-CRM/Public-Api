# Company Management API

The Company Management API allows you to manage companies in your TaskIP CRM system. You can create, read, update, search, and delete companies, as well as perform bulk deletes.

<Callout type="info" emoji="💡">
  **Resource IDs**: The `{id}` segment of the company routes only accepts digits. A non-numeric segment (for example `/company/tags`) is a `404`.
</Callout>

## Endpoints Overview

| Method | Endpoint | Description |
|--------|----------|-------------|
| `GET` | [`/api/public-v1/company`](#get-all-companies) | Get all companies |
| `POST` | [`/api/public-v1/company`](#create-a-company) | Create a new company |
| `GET` | [`/api/public-v1/company/{id}`](#get-a-specific-company) | Get a specific company |
| `PUT` / `PATCH` | [`/api/public-v1/company/{id}`](#update-a-company) | Update a company |
| `DELETE` | [`/api/public-v1/company/{id}`](#delete-a-company) | Delete a company |
| `POST` | [`/api/public-v1/company/bulk-delete`](#bulk-delete-companies) | Delete multiple companies |
| `GET` | [`/api/public-v1/company-search`](#search-companies) | Search companies by name |
| `GET` | [`/api/public-v1/company-tag`](#list-company-tags) | List company tags |
| `POST` | [`/api/public-v1/company-tag`](#create-a-company-tag) | Create a company tag |

## Get All Companies

Retrieve a paginated list of all companies in your system.

```http
GET /api/public-v1/company
```

<ApiTester
  endpoint="/api/public-v1/company"
  method="GET"
  description="Retrieve all companies from your TaskIP system with filtering and pagination options"
/>

### Request Headers
```http
X-Secret-Key: your-secret-key-here
Content-Type: application/json
```

### Query Parameters
| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `page` | integer | No | Page number for pagination (default: 1) |
| `item` | integer | No | Companies per page (default: 10). Use `0` to return all companies without pagination |
| `search` | string | No | Search by company name, email, or phone number |
| `industry_id` | integer or array | No | Filter by industry ID(s), e.g. `industry_id[]=2&industry_id[]=5` |
| `industry_is_empty` | boolean | No | When true, only companies without an industry are returned (overrides `industry_id`) |
| `number_of_employees_operator` | string | No | Employee-count comparison: `equals`, `gt`, `gte`, `lt`, `lte`, or `between`. Used together with `number_of_employees_value` |
| `number_of_employees_value` | integer | No | Value to compare against |
| `number_of_employees_value2` | integer | No | Upper bound when the operator is `between` |
| `number_of_employees_is_empty` | boolean | No | When true, only companies without an employee count are returned (overrides the operator filter) |

Results are ordered by `id` descending.

### Example Request

```bash
curl -X GET "https://public-api.taskip.net/api/public-v1/company?page=1&item=20&search=acme" \
  -H "X-Secret-Key: your-secret-key-here" \
  -H "Content-Type: application/json"
```

### JavaScript Example
```javascript
const response = await fetch('https://public-api.taskip.net/api/public-v1/company?page=1&item=20', {
  method: 'GET',
  headers: {
    'X-Secret-Key': 'your-secret-key-here',
    'Content-Type': 'application/json'
  }
});

const companies = await response.json();
```

## Create a Company

Create a new company in your system.

```http
POST /api/public-v1/company
```

<ApiTester
  endpoint="/api/public-v1/company"
  method="POST"
  defaultBody={{
    "name": "Green Energy Solutions",
    "email": "contact@greenenergy.com",
    "phone_number": "+1-555-0102",
    "website": "https://www.greenenergy.com",
    "c_size": 4,
    "c_type": 12,
    "number_of_employees": 250,
    "country_id": 1,
    "state_id": 15,
    "city_id": 120,
    "address": "789 Sustainability Blvd, Austin, TX 78701",
    "zip_code": "78701"
  }}
  description="Test creating a new company in your TaskIP system"
/>

### Request Headers
```http
X-Secret-Key: your-secret-key-here
Content-Type: application/json
```

### Request Body

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `name` | string | Yes | Company name (max 191 characters) |
| `email` | string | Yes | Company email. Must not already belong to a user, another company, or a lead (unless your workspace allows duplicate company emails) |
| `phone_number` | string | No | Company phone number |
| `website` | string | No | Company website, must be a valid URL such as `https://example.com` (max 191 characters) |
| `c_size` | integer | No | Company size ID (numeric) |
| `c_type` | integer | No | Company type ID (numeric) |
| `number_of_employees` | integer | No | Number of employees (min 0) |
| `industry_id` | integer | No | Industry ID |
| `country_id` | integer | No | Country ID |
| `state_id` | integer | No | State/Province ID |
| `city_id` | integer | No | City ID |
| `address` | string | No | Company address |
| `zip_code` | string | No | ZIP/postal code (max 20 characters) |
| `vat_id` | string | No | VAT ID (max 100 characters) |
| `tags` | array of integers | No | Tag IDs to put on the company, from [Company Tags](#company-tags). An ID that does not exist is a `422` and nothing is saved |
| `company_members` | array | No | Array of user IDs (each must exist in users) |
| `custom_fields` | array | No | Custom field data. Required custom fields defined in your workspace are enforced |
| `description` | string | No | Free-text description |

<Callout type="info" emoji="💡">
  **Persisted fields**: Create and update store `name`, `email`, `phone_number`, `website`, `c_size`, `c_type`, `number_of_employees`, `industry_id`, `country_id`, `state_id`, `city_id`, `address`, `zip_code`, `vat_id`, `description`, `tags`, `company_members` and `custom_fields`. When `tags`, `company_members` or `custom_fields` is empty or left out, the company keeps what it already has.
</Callout>

### Example Request

```bash
curl -X POST "https://public-api.taskip.net/api/public-v1/company" \
  -H "X-Secret-Key: your-secret-key-here" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Green Energy Solutions",
    "email": "contact@greenenergy.com",
    "phone_number": "+1-555-0102",
    "website": "https://www.greenenergy.com",
    "c_size": 4,
    "c_type": 12,
    "country_id": 1,
    "state_id": 15,
    "city_id": 120,
    "address": "789 Sustainability Blvd, Austin, TX 78701",
    "tags": [12]
  }'
```

### Python Example
```python

    'X-Secret-Key': 'your-secret-key-here',
    'Content-Type': 'application/json'
}

    "name": "Green Energy Solutions",
    "email": "contact@greenenergy.com",

    "website": "https://www.greenenergy.com",

    "country_id": 1,
    "state_id": 15,
    "city_id": 120,

}

response = requests.post(
    'https://public-api.taskip.net/api/public-v1/company',
    headers=headers,
    json=company_data
)

result = response.json()
```

## Update a Company

Update an existing company's information.

```http
PUT /api/public-v1/company/{id}
PATCH /api/public-v1/company/{id}
```

`PUT` and `PATCH` are handled identically and share the same validation rules as create. The company in the URL is the one updated; no new company is created.

<ApiTester
  endpoint="/api/public-v1/company/1"
  method="PUT"
  defaultBody={{
    "name": "Green Energy Solutions Updated",
    "email": "info@greenenergy.com",
    "phone_number": "+1-555-0103",
    "website": "https://www.greenenergy.com",
    "c_size": 5,
    "c_type": 12,
    "country_id": 1,
    "state_id": 15,
    "city_id": 120,
    "address": "789 Sustainability Blvd, Suite 200, Austin, TX 78701"
  }}
  description="Test updating a company's information"
/>

### Path Parameters
| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `id` | integer | Yes | Company ID to update (digits only) |

### Request Body

Same fields as [Create a Company](#create-a-company). `name` and `email` are required on every update, even with `PATCH`. A company can keep its own current email.

`tags` **replaces** the company's tags with the IDs you send. To add a tag without touching the others, send the full list including the existing ones. Leaving `tags` out, or sending an empty list, keeps the current tags. Additionally:

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `image` | integer | No | Media upload ID. Replaces the company's current image |

### Example Request

```bash
curl -X PUT "https://public-api.taskip.net/api/public-v1/company/46" \
  -H "X-Secret-Key: your-secret-key-here" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Green Energy Solutions Updated",
    "email": "info@greenenergy.com",
    "phone_number": "+1-555-0103",
    "c_size": 5,
    "address": "789 Sustainability Blvd, Suite 200, Austin, TX 78701"
  }'
```

### Example Response

The response status is `202 Accepted`.

```json
{
  "msg": "Company update success"
}
```

## Bulk Delete Companies

Delete multiple companies at once.

```http
POST /api/public-v1/company/bulk-delete
```

<ApiTester
  endpoint="/api/public-v1/company/bulk-delete"
  method="POST"
  defaultBody={{
    "ids": [1, 2, 3, 4]
  }}
  description="Test bulk deleting multiple companies (use with caution)"
/>

### Request Body

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `ids` | array | Yes | Array of company IDs to delete (1 to 1000 items) |
| `ids.*` | integer | Yes | Each ID must be an integer that exists in the companies table |

### Example Request

```bash
curl -X POST "https://public-api.taskip.net/api/public-v1/company/bulk-delete" \
  -H "X-Secret-Key: your-secret-key-here" \
  -H "Content-Type: application/json" \
  -d '{
    "ids": [44, 45, 47, 48]
  }'
```

### JavaScript Example
```javascript
const bulkDeleteData = {
  ids: [44, 45, 47, 48]
};

const response = await fetch('https://public-api.taskip.net/api/public-v1/company/bulk-delete', {

    'Content-Type': 'application/json'
  },
  body: JSON.stringify(bulkDeleteData)
});

const result = await response.json();
```

### Example Response

The response status is `202 Accepted`.

```json
{
  "msg": "companies deleted."
}
```

## Company Tags

A tag is a coloured label such as `Company`, `Individual` or `Trust`. Companies take tags by **ID**, so create each tag once, keep its ID, and send that ID in `tags` when you create or update companies. Tags created here are always company tags, whatever `type` you send.

### List Company Tags

```http
GET /api/public-v1/company-tag
```

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `search` | string | No | Search tags by name |
| `item` | integer | No | Tags per page |
| `page` | integer | No | Page number |

```bash
curl -X GET "https://public-api.taskip.net/api/public-v1/company-tag?search=trust" \
  -H "X-Secret-Key: your-secret-key-here"
```

```json
{
  "data": [
    { "id": 12, "name": "Trust", "color": "#336699", "type": "company" }
  ],
  "links": { "first": "...", "last": "...", "prev": null, "next": null },
  "meta": { "current_page": 1, "per_page": 10, "total": 1 }
}
```

### Create a Company Tag

```http
POST /api/public-v1/company-tag
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `name` | string | Yes | Tag name (max 191 characters) |
| `color` | string | Yes | Tag colour, for example `#336699` (max 50 characters) |

```bash
curl -X POST "https://public-api.taskip.net/api/public-v1/company-tag" \
  -H "X-Secret-Key: your-secret-key-here" \
  -H "Content-Type: application/json" \
  -d '{ "name": "Trust", "color": "#336699" }'
```

The response status is `201 Created`.

```json
{
  "msg": "Tag created",
  "data": { "id": 12, "name": "Trust", "color": "#336699", "type": "company" }
}
```

<Callout type="info" emoji="💡">
  **Tag IDs can be large.** Keep them as 64-bit integers (or strings) in your own code, and send the IDs exactly as the API returned them.
</Callout>

### Unknown tag IDs

If any ID in `tags` does not exist, the request is refused with `422` and no company is created or changed:

```json
{
  "error": {
    "tags.0": ["The selected tags.0 is invalid."]
  }
}
```

### Tag companies when you import them

1. `GET /company-tag?search=Trust` and, if it is not there, `POST /company-tag`. Store the ID for `Company`, `Individual` and `Trust`.
2. `POST /company` with `"tags": [<id>]` for each new company.
3. For a company that already exists, `PUT /company/{id}` with the tag in `tags`. Send every tag the company should have, since the list replaces the current one.

## Error Responses

### Common Error Codes

| Status Code | Error Type | Description |
|-------------|------------|-------------|
| `401` | Unauthorized | Invalid or missing X-Secret-Key |
| `404` | Not Found | Company not found, or a non-numeric ID in the path |
| `422` | Validation Error | Request data failed validation |
| `429` | Too Many Requests | Rate limit exceeded |

### Example Error Response

Validation failures return `422` with the failing fields under `error`:

```json
{
  "error": {
    "name": ["The name field is required."],
    "email": ["The email field must be a valid email address."],
    "website": ["Website must be a valid URL (example: https://example.com)."]
  }
}
```

## Best Practices

### Company Creation
1. **Use consistent naming**: Keep company names consistent across your CRM
2. **Use unique emails**: Company emails are checked against users, other companies and leads
3. **Industry categorization**: Use standardized industry IDs for better filtering
4. **Complete profiles**: Add as much company information as possible for better CRM insights

### Data Management
1. **Regular updates**: Keep company information current
2. **Bulk operations**: Use bulk delete for efficient data management
3. **Search optimization**: Use descriptive names for better searchability with `company-search`

<Callout type="info" emoji="💡">
  **Tip**: Use the `industry_id` and `number_of_employees_*` filters in the GET /company endpoint to segment your companies. This is particularly useful for targeted marketing campaigns or industry-specific reporting.
</Callout>
