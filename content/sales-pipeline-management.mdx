# Sales Pipeline Management API

The Sales Pipeline Management API is a comprehensive system for managing sales processes, deals, stages, tasks, meetings, files, notes, and activities. This powerful API allows you to build complete CRM workflows and sales automation systems.

## Overview

Sales Pipeline API consists of multiple interconnected modules:
- **Pipeline Management**: Main pipeline operations
- **Deals Management**: Individual deal lifecycle
- **Stages Management**: Pipeline stage configuration  
- **Tasks Management**: Deal-specific task tracking
- **Files Management**: Document handling for deals
- **Meetings Management**: Schedule and manage meetings
- **Notes Management**: Deal notes and communication
- **Activities Management**: Activity tracking and logging
- **Attributes Management**: Custom pipeline attributes

## Get All Sales Pipelines

Retrieve a list of all sales pipelines in your system.

```http
GET /api/public-v1/sales-pipeline
```

### Request Headers
```http
X-Secret-Key: your-secret-key-here
Content-Type: application/json
```

### Query Parameters
| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `page` | integer | No | Page number for pagination |
| `item` | integer | No | Pipelines per page (default: 10). `0` returns all pipelines |
| `search` | string | No | Search term for the pipeline title |

Results are ordered newest first. Team members who are not administrators or managers only see pipelines that contain deals they own or are assigned to.

### Example Request

```bash
curl -X GET "https://public-api.taskip.net/api/public-v1/sales-pipeline?item=20" \
  -H "X-Secret-Key: your-secret-key-here" \
  -H "Content-Type: application/json"
```

## Create a Sales Pipeline

Create a new sales pipeline with initial configuration.

```http
POST /api/public-v1/sales-pipeline
```

### Request Body

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `title` | string | Yes | Pipeline title (max 191 characters) |
| `status` | integer | No | `0` Draft, `1` Publish (not validated) |

Six default stages are created with the pipeline: Prospecting, Qualification, Proposal/Quotation, Negotiation/Review, Closed/Won and Closed/Lost.

### Example Request

```bash
curl -X POST "https://public-api.taskip.net/api/public-v1/sales-pipeline" \
  -H "X-Secret-Key: your-secret-key-here" \
  -H "Content-Type: application/json" \
  -d '{
    "title": "Enterprise Sales Pipeline",
    "status": 1
  }'
```

### Example Response

```json
{
  "msg": "Sales Pipeline stored successfully.",
  "data": {
    "title": "Enterprise Sales Pipeline",
    "status": 1,
    "uuid": "pipeline-xyz789abc123",
    "created_at": "just now",
    "stages_count": null
  }
}
```

The response status is `201`.

### Error Responses

| Status | Description |
|--------|-------------|
| `403` | The user does not have permission to create sales pipelines |
| `422` | Validation failed: `{ "error": { "title": ["..."] } }` |

## Update a Sales Pipeline

Update the title of an existing sales pipeline. `PUT` and `PATCH` are handled identically: the request is validated like [Create a Sales Pipeline](#create-a-sales-pipeline), so `title` is required, and only `title` is written (`status` is ignored on update).

```http
PUT /api/public-v1/sales-pipeline/{uuid}
PATCH /api/public-v1/sales-pipeline/{uuid}
```

### Path Parameters
| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `uuid` | string | Yes | Sales pipeline UUID |

### Request Body
| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `title` | string | Yes | Pipeline title (max 191 characters) |

### Example Request

```bash
curl -X PUT "https://public-api.taskip.net/api/public-v1/sales-pipeline/pipeline-abc123def456" \
  -H "X-Secret-Key: your-secret-key-here" \
  -H "Content-Type: application/json" \
  -d '{
    "title": "Updated Sales Pipeline"
  }'
```

### Example Response

```json
{
  "msg": "Pipeline Updated Successfully",
  "data": {
    "title": "Updated Sales Pipeline",
    "status": 1,
    "uuid": "pipeline-abc123def456",
    "created_at": "2 weeks ago",
    "stages_count": null
  }
}
```

### Error Responses
| Status | Description |
|--------|-------------|
| `404` | `{ "msg": "pipeline not found" }` |
| `422` | Validation failed: `{ "error": { "title": ["..."] } }` |

## Create a Deal

Create a new deal in a sales pipeline.

```http
POST /api/public-v1/sales-pipeline/{uuid}/deals
```

### Path Parameters
| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `uuid` | string | Yes | Sales pipeline UUID |

### Request Body
| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `deal_name` | string | Yes | Deal name (max 191 characters) |
| `deal_owner_id` | integer | Yes | Deal owner user ID |
| `deal_stage_id` | integer | Yes | Stage ID the deal belongs to |
| `contact_id` | integer | Conditional | Contact ID. Either `contact_id` or `lead_id` is required |
| `lead_id` | integer | Conditional | Lead ID. Either `contact_id` or `lead_id` is required |
| `company_id` | integer | No | Company ID |
| `deal_amount` | integer | No | Deal amount (default: `0`) |
| `deal_status` | integer | No | `0` Open (default), `1` Negotiation, `2` Won, `3` Lost |
| `closing_date` | string | No | Closing date |
| `description` | string | No | Deal description |
| `currency` | string | No | Currency code |
| `status` | integer | No | Deal status flag (default: `1`) |
| `priority` | integer | No | Priority (default: `0`) |
| `lead_type` | integer | No | `0` Cold (default), `1` Warm, `2` Hot |
| `tags` | array | No | Array of sales pipeline attribute IDs |
| `documents` | array | No | Array of document IDs |
| `from_email` | string | No | From email |
| `custom_fields` | array | No | Custom field values |
| `invite_client` | boolean | No | Send a portal invitation to the contact (create only effect) |

### Example Request

```bash
curl -X POST "https://public-api.taskip.net/api/public-v1/sales-pipeline/pipeline-abc123def456/deals" \
  -H "X-Secret-Key: your-secret-key-here" \

    "deal_status": 0,
```

## Update a Deal

Update an existing deal. `PUT` and `PATCH` are handled identically and the deal must belong to the pipeline in the URL. The body is validated like [Create a Deal](#create-a-deal), so `deal_name`, `deal_owner_id`, `deal_stage_id` and `contact_id` / `lead_id` (at least one of the two) must always be sent. The remaining optional fields are partial: `company_id`, `contact_id`, `lead_id`, `deal_amount`, `deal_status`, `closing_date`, `description`, `currency`, `status`, `from_email`, `priority`, `lead_type`, `tags` and `documents` keep their stored values when omitted. Send `tags` or `documents` as an empty array to remove them all.

# Response Patterns

- All endpoints require the `X-Secret-Key` header.
- Validation failures from form requests return `422` with `{ "error": { "<field>": ["message"] } }`. A few endpoints without a custom form request (pipeline list, deals list, deals order change, attributes) return the standard Laravel shape `{ "message": "...", "errors": { ... } }`.
- Business-rule and permission refusals use `422` with `{ "error": { "msg": ["..."] } }` or `{ "msg": "..." }`.
- Unknown resources return `404` with `{ "msg": "..." }`.
- `PUT` and `PATCH` are both routed to the update handler of every resource that supports updates (pipeline, deal, stage, task, meeting, note, activity, attribute). They behave identically and the same required fields must be sent. The only partial update is the deal: its optional fields keep their stored values when omitted (see [Update a Deal](#update-a-deal)).
- `GET /{id}` routes do not exist for stages, notes, activities and attributes.
